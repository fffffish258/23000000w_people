# [剩食與雜物互助系統] 產品需求文件 (PRD)

## 1. 專案概述

### 背景與動機
在大學宿舍生活中，學生經常會遇到購買過多食物而無法在效期內食用完畢，或是搬家/大掃除時產生許多還能使用但不打算帶走的雜物。直接丟棄這些物資不僅造成資源浪費，也十分可惜。本系統旨在建立一個簡易、直觀的互助平台，讓校園內的剩食與雜物能快速找到下一個主人。

### 目標用戶
- 大學生（特別是住宿生與租屋生）

### 核心價值主張
- **減少浪費**：讓即將過期的食物或不再需要的雜物發揮餘溫。
- **資源共享**：建立友善的校園互助社群。
- **即時資訊**：透過自動過期與狀態管理，確保布告欄資訊的準確性。

## 2. 功能需求

### 使用者故事 (User Stories)

| 功能模組 | 使用者故事 |
| :--- | :--- |
| **物品資訊發佈** | 作為提供者，我希望能夠輸入物品名稱、描述與上傳圖片網址，以便讓其他同學了解我提供的物資資訊。 |
| **關鍵字查詢檢索** | 作為索取者，我希望能夠透過輸入關鍵字，以便在眾多資訊中快速找到我感興趣的特定物品。 |
| **狀態管理與下架** | 作為提供者，我希望在物品被領取後將其標記為「已領取」或「刪除」，以便避免其他人重複詢問或撲空。 |
| **自動過期隱藏** | 作為索取者，我希望系統能自動隱藏已過期的食品資訊，以便確保我看到的食品列表都是在有效期限內的。 |
| **分類標籤與篩選** | 作為使用者，我希望可以一鍵切換「食品」與「雜物」分類，以便根據我的即時需求（餓了或需要工具）快速瀏覽。 |
| **圖片顯示** | 作為索取者，我希望在列表看到物品的微縮圖，以便在點擊詳情前能對物品現狀有初步判斷。 |

## 3. 非功能需求

### 技術限制
- **開發框架**：Flask (Python)
- **模板引擎**：Jinja2
- **資料庫**：SQLite
- **前端美感**：需符合現代、活潑且直觀的 UI 設計（Vanilla CSS）。

### 效能與安全考量
- **自動過濾邏輯**：後端需在每次查詢時準確比對伺服器目前時間與 `expiry_date`。
- **圖片載入**：優化縮圖顯示，避免大圖直接載入造成列表緩慢。
- **輸入驗證**：防止惡意指令或不正確的日期格式輸入。

## 4. MVP 範圍

### Must Have (必須達成)
- 物品發佈功能（包含食品有效日期欄位）。
- 帶有圖片縮圖的布告欄列表。
- 食品/雜物一鍵篩選功能。
- 關鍵字搜尋功能。
- 自動過期隱藏邏輯（針對食品）。
- 手動變更狀態為「已領取」或刪除功能。

### Should Have (應該要有)
- 基礎的使用者簡易身分區分（例如：透過簡單的 Session 或 Password 來管理自己發布的物品）。
- 倒數計時提示：標示食品還有多久過期。

### Nice to Have (以後再說)
- 站內即時留言/私訊功能。
- 多校區/宿舍區域篩選。
- 物品類別更細緻的標籤（如：文具、家電、零食、正餐）。

## 6. 資料欄位初步規劃 (參考)

- **id**: 唯一識別碼
- **title**: 物品名稱
- **description**: 物品描述
- **category**: 分類 (Food / Misc)
- **image_url**: 圖片連結
- **expiry_date**: 有效日期 (食品必填)
- **status**: 狀態 (Available / Taken)
- **created_at**: 建立時間
